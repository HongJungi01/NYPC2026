## 1. 확정된 게임 메커니즘 (코드 상수로 교차 확인)

토론에서 합의됐고 `submission/hybrid.cpp` 상수와 일치하는 하드 팩트.

| 사실 | 값 / 근거 |
|---|---|
| 이동 명령은 새로 받는 병사마다 **10골드**, 단 목적지가 **아군 건물이면 0** | `MOVE_COST=10` [hybrid.cpp:34](../submission/hybrid.cpp#L34), 무료 분기 `issue_move` [:728](../submission/hybrid.cpp#L728) |
| 유닛 처치는 골드를 주지 않지만 **상대 재생산비 120골드 + 미래 생산력**을 부정 | `TRAIN_COST=120` [:35](../submission/hybrid.cpp#L35) |
| 건물 1채 = **300골드**, 일당 수입 `15 × min(주둔 인원, work_cap)` | `BASE_BUILD_COST=300`, `WORK_INCOME=15` [:36-37](../submission/hybrid.cpp#L36) |
| 병사 유지비 일당 **2골드**, 골드 0이면 굶어 hp 감소 | `UPKEEP_PER_WARRIOR=2` [:38](../submission/hybrid.cpp#L38) |
| **HQ 레벨↑ → 생성 유닛 HP 4→5→6→7→8**, work_cap 1→5, train_cap 1→3, 터렛/HQ HP↑ | `HQ_LEVELS` [:51-54](../submission/hybrid.cpp#L51) |
| 시작: 골드 500, 병사 3명, 200턴 | `START_GOLD/START_WARRIORS/MAX_TURN` [:31-33](../submission/hybrid.cpp#L31) |
| **완전정보 제로섬** — 시야 없음. referee가 매 턴 양측 이벤트를 전부 보냄. **골드만 은닉** | 관측 모델은 [§4](#4-전장-관측-모델) 참조 |

함의:
- **유닛 1명의 가치가 크다.** 초반 일당 1명 생성이라 손실 회복이 느리다. 트레이드는 최소
  병력-건물 교환급이어야 이득(단순 1:1 병력 교환은 손해).
- **러쉬는 거의 비유효.** 상대가 300골드 건물을 올리는 동안 병력을 쏟아부어도 건물이 공격 1로
  받아쳐서 수적 우위를 내기 어렵다. → 경제 우선.
- **승부의 축 = 기지를 몇 개 얼마나 빨리 먹느냐(=골드 수급).** 그 기지를 **최소 병력으로 지키고
  최소 병력으로 공격**하는 효율이 핵심.

## 3. 적용 우선순위 (백로그)

> ⚠ 아래는 전부 eval/`gen_cmds` 휴리스틱 영역으로, **오버피팅·회귀가 상습**인 곳이다. 채택은
> 반드시 **같은 seed 페어 대조**(같은 맵에서 -a/-b 스왑 2판)로 검증한다. 단판 승패는 보드 분산에 묻힌다.

1. **중앙땅 턴 게이트 가치 + 요격 길목** — 중앙 stronghold를 `expand_order`에서 turn ≥ ~50 게이트로
   승격하고, `eval_state`에 중앙 점유/요격 항을 추가. 점대칭 리테이크(상대 300골드 투자 시 ~2.5명
   우위) 가설을 시뮬로 검증.
2. **초반 결정적 오프닝 빌드오더** — 3땅 개막 시퀀스 + "건설비를 못 대면 채굴 선행". 중반 경제 가속.
3. **킬 가치 / 트레이드 품질** — eval에서 유닛 손실을 재생산비(120)로 가중, 불리한 트레이드 공격을
   게이트. (`min_mass`로 부분 커버 → 우선순위 낮음)
4. **알파베타 골드 최적화** — 대공수. BOSS makespan 탐색과 묶어 별도 과제로 보류.

## 4. 전장 관측 모델

referee는 매 턴 양측의 이벤트 블록(UPGRADE/TRAIN/MOVE/DAMAGE/SIEGE)을 봇에 보내고 **골드는 양측 다
숨긴다.** 따라서:

- **적 유닛 위치·칸별 수·건물·레벨 = 정확 관측** — `init_sim`이 시작 상태를, `read_turn_result`가
  이벤트를 누적해 양측 `SimState`를 복원한다. *추정이 아니라 관측이다.*
- **상대 골드만 진짜 은닉** → 추정(시작 500 − 관측 지출 + 수입 − upkeep). 그중 **이동비 타이밍**만
  근사원(빌드/훈련/수입/upkeep은 정확). 이 추정 정밀화 + 복원 정확성 검증은 별도 WorldModel 작업으로 진행 중.
