# submission 운영 정책 (버전 스냅샷 + 교차대전 테스트)

봇 코드의 변경 이력을 **불변 스냅샷으로 누적**하고, 누적된 봇들끼리 **교차 대전으로
관찰만** 하는 체제. 봇 진화를 타임라인으로 보존하고, 다양한 상대 스파링 풀을 만든다.

## 1. 파일 규칙
- `<MMDDHHmm>[r|d].cpp` = 봇 버전 **스냅샷**(불변). 봇 코드를 의미 있게 바꿀 때마다 그 시각으로
  새 파일을 만든다. 예: 7월 1일 11:37 → `07011137.cpp`.
- **접미 1자 = 반영 출처 표식** (2026-07-02 도입):
  - `r` = **단순 로그분석 반영** 스냅 — `/analyze-logs`(또는 사람 수기) 분석 md를 반영해 만든 코드.
    예: `07021530r.cpp`. (일체형 `/analyze-reflect` 산출물 포함.)
  - `d` = **스냅샷대조(deep) 분석 반영** 스냅 — `/analyze-logs-deep`의 코드 대조 DEEP 분석 md를
    반영해 만든 코드. 예: `07021530d.cpp`. (일체형 `/analyze-reflect-deep` 산출물 포함.)
  - 무접미 = 수동/기타 변경(튜닝·리팩터 등, 기존과 동일).
- **HEAD = 가장 최신 스냅샷**(타임스탬프 기준, 접미 무관; 같은 타임스탬프면 접미 쪽이 뒤)
  = 현재 봇 = **대회 제출 파일**. 다음 변경은 최신 스냅샷을 복사해
  새 스냅샷으로 이어간다(이전 스냅샷은 그대로 둔다). **HEAD가 아닌 모든 봇 = 레거시**(§6 전면 동결).
- `main.cpp` = **대회 업로드 사본**(2026-07-02부터; 과거 mgr5 베이스라인과 무관). 사용자가
  제출할 스냅샷을 이 이름으로 복사해 올린다(현재 = 07021621과 동일). 도구는 이 파일을
  스냅샷 풀에 넣지 않는다(8자리 패턴 불일치) — abtest의 `-Base`로 지정해 쓸 수 있다.
- `hybrid.cpp` = **동결(retired)**. 과거 작업 파일이며 최신 스냅샷의 조상. 편집하지 않는다.
- 빌드: `g++ -O2 -std=c++17 <name>.cpp -o <name>.exe` (PowerShell, 필요시
  `$env:PATH = "C:\msys64\ucrt64\bin;" + $env:PATH`). `.exe`는 .gitignore(재생성 가능).

## 2. 교차대전 테스트 (`crossplay.ps1`)
- 새 스냅샷을 추가하면 실행: 그 스냅샷("New") vs **다른 모든 참가자**(이전 스냅샷들 + 있으면 베이스라인).
- 참가자당 **서로 다른 10개 시드 × 1판**(맵이 점대칭이라 좌우 스왑 불필요).
- referee: `Seongho/Game_NEXT_NATION_ver1/engine/testing-tool-practice.py`
  (`--seed S -l <log> -a <New.exe> -b <opp.exe>`). New는 항상 LEFT(-a).
- 실행: `powershell -File submission/crossplay.ps1 [-New <MMDDHHmm>]` (생략 시 최신 스냅샷).

## 3. 결과 로그
- 요약: `Logs/Test/<New>_crossplay.md` — 상대 × 시드 그리드(W/L/D) + W-L-D 집계. **커밋한다.**
- raw referee 로그: `Logs/Test/raw/<New>/` — 경기당 수천 줄이라 **.gitignore**(로컬 분석용).
  패인이 보이면 [[../Logs/POLICY.md]] 반영 루프로 가져갈 수 있다.

## 4. 자가대전 A/B 튜닝 (2026-07-01 도입 — 기존 "관찰 전용" 해제)
- **`crossplay.ps1`(교차대전)은 여전히 관찰 전용**: 결과로 롤백/무의미판정/채택거부 안 함.
- **`abtest.ps1`(A/B)로는 승률 튜닝을 한다**: 후보 vs 베이스라인을 **동일 풀·동일 시드** 페어로
  돌려 W-L-D로 채택/기각. 풀 = 8자리(+선택 접미 1자) 스냅샷 **+ 고정포스처 spar 봇**(`spar_base.cpp`에서
  `-DSCRIPT_BOT -DSCRIPT_POLICY=presets::RUSH|TURTLE|EXPAND|BALANCED`). 오버피팅 완화의 핵심은
  **풀 다양화**(계보만 아니라 spar 포함)다.
- 채택 룰: **뚜렷한 net 개선 + 단일상대 비회귀 + 메커니즘 근거**. 미미/혼조는 베이스 유지.
  정확성 게이트(SIM/OBS)는 항상 선행. ⚠️ 풀에 **외부 봇이 없어** 외부상대 대응 변경의 *이득*은
  측정 불가 — 그런 변경은 메커니즘 근거로 판단.
- 근거: 정확성 게이트만으론 **전략 회귀를 못 잡는다**(2026-07-01 리워크 2건이 게이트 통과했으나
  A/B에서 큰 회귀로 드러나 되돌림). 방침 상세 = 메모리 `dev-testing-cadence`.
- (2026-07-03, §6) 단 **분석 유래 기능 반영에는 분석 우선 원칙**: 레거시 풀 A/B 성적은 승패 평가
  지표(참고)일 뿐, 그것만으로 실전 로그 분석 finding 기반 기능을 기각·제거하지 않는다.
  큰 회귀가 관찰되면 자동 기각 대신 **사람에게 플래그**해 판단을 맡긴다.

## 5. 전략 변형 스파링 풀 (`variants.cpp` + `buildpool.ps1`, 2026-07-02 도입)
- `variants.cpp` = **동결 시점 main.cpp 사본 + 컴파일타임 노브** (§6 전면 동결, 2026-07-03).
  main.cpp가 갱신돼도 **재사본·재동기화하지 않는다** — 평가 기준선을 안정적으로 유지하기 위해
  의도적으로 분기를 허용한다. (동결 전 규칙이던 "전처리 결과 == main.cpp" 검사는
  buildpool.ps1의 opt-in `-Check`로만 남음.)
- `powershell -File submission/buildpool.ps1` → `var_rush/greed/turtle/harass.exe` 4종 빌드.
  전부 **룩어헤드 유지**(SCRIPT_BOT 아님) — 구세대 spar_*보다 훨씬 강한 "똑똑한 다양성":
  - `var_rush` 초반 압박(공세 조기·병력 우선·기지 2개 정지) · `var_greed` 확장 몰빵(클레임+1·병력 최소)
  - `var_turtle` 요새+조기 판정 래더(기지 2개 정지·큰 상비군) · `var_harass` 상시 수입 말리기(스쿼드 8)
- `abtest.ps1` 풀이 `var_*.exe`를 자동 편입한다(spar_*와 병행). 적응형/전략 변경의 채택 기준에
  **"var_* 4종 전부 net ≥ 0"**을 추가로 본다(성향 대응 검증). ⚠️ 풀은 여전히 자기 계보 파생 —
  풀 승률은 필요조건일 뿐, 외부 검증은 웹 실전 로그(/analyze-logs 루프)로 한다.

## 6. 레거시 봇 전면 동결 (2026-07-03)

**레거시** = HEAD가 아닌 모든 8자리 스냅샷(접미 포함) + `hybrid.cpp` + `spar_base.cpp` +
`variants.cpp`(및 빌드 산출 `spar_*`/`var_*`.exe). 용도 = crossplay 상대·abtest 풀 멤버,
즉 **승패 평가 전용**.

- **평가 결과의 지위(핵심)**: 레거시 풀 대전 성적은 **승패 평가 지표일 뿐, 기능 결정의 근거가
  아니다** — "이 기능이 레거시전에서 이런 평가를 받았으니 뺀다/고친다" 식 결정 금지. 기능에 대한
  조언·첨삭은 **실전 로그 분석(analyze 파이프라인) finding을 우선 채택**한다: 실제 경기 로그에
  결과로 나타난 문제가 진짜 문제다. (§4·§5의 "풀 승률은 필요조건, 외부 검증은 웹 실전 로그"
  방침의 강화판. reflect-analysis §4 "분석 우선 원칙"과 동일.)
- **파일 동결(엄격)**: 레거시 파일에 기능 추가·수정·버그픽스·튜닝·리팩터·삭제·리네임·풀 제외
  일절 금지. 레거시에서 버그를 발견해도 픽스하지 않는다(진단·플래그만). 새 기능/수정은 항상
  HEAD 복사 → 새 스냅샷으로만.
- **허용**: `.exe` 재빌드(재생성 가능 산출물), 읽기·분석(DEEP 대조 등).
- **예외**: 사람 명시 승인 시에만 + `Logs/LEDGER.md`에 기록.
- variants.cpp의 main.cpp 재동기화 규칙(§5)은 폐지 — 동결 시점 사본으로 고정, main.cpp와
  의도적 분기(buildpool.ps1 동일성 검사는 opt-in `-Check`로 반전).
