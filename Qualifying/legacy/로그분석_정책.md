# 정책: 배틀 로그 → 판단근거 역추적 → 대처방향 (Loss-Turn Root-Cause Loop)

> 사용자가 특정 배틀의 특정 턴을 "여기서 ○○ 때문에 손해"라고 짚으면, 그 오더가 **왜 나왔는지
> 코드에서 역추적**하고, 사용자가 그 근거를 틀렸다고 판정하면 **"이런 상황엔 이렇게" 대처방향**을
> 잡는다. 대처방향을 사용자가 승인하면 **그때 코드를 고치고, 한 판 정합성 스모크로만 확인한 뒤
> 다음 문제로 넘어간다(빠른 루프 — SIM/OBS 200턴 매치 안 돌림).**

## 입력 3종과 신뢰도 등급 (섞지 않는다)

| 입력 | 무엇 | 신뢰도 |
|---|---|---|
| **로그** | `Logs/Reflected/_facts/*.facts.md` (실측: 궤적·전투·공성·건물·타이밍) | **팩트** — "무슨 일이 일어났나"는 여기서만 확정 |
| | facts.md의 골드 열 | **역산 하한** (drift 이후 실제 ≥ 표기) — 절대비교 금지, 추세만 |
| | 원본 `.txt` | 오더 원문 (필요 시 대조) |
| | `.md` 리플렉션 | **해석** — 판단근거 아님, 참고만 |
| **코드** | `redesign/bot.cpp` — `decide()`(≈1034–1799) + `strategy_manager`(≈1804) + `eval_state`(≈990) | 판단근거의 **유일한 출처** |
| **설계의도** | `남기고자_하는_기능.md` (keep/kill/transform 근거) | 그 동작이 **의도됐는지** 판정 |

## 턴마다 4블록 산출 (고정 포맷)

**① 관찰 (FACT)**
facts.md 실측으로 그 턴에 코드가 *실제로 한 것*만. 궤적표·전투표·골드추세로 확정. 추측 0.

**② 판단근거 (WHY) — 코드 역추적**
`decide()`의 어느 섹션이 그 오더를 냈는지 **실제 줄·조건을 인용**해서 짚는다.
- 강제수는 `decide()`가 직접, **잉여군 배분은 `strategy_manager` 롤아웃**이 결정 — 어느 loci인지 구분.
- 여러 섹션이 상호작용하면 **발화 순서대로**.
- **규칙: 발화 조건을 코드에서 못 찾으면 "코드에서 확인 안 됨"이라고 명시한다. 근거 날조 금지.**
  불확실하면 `(추정)` 캐버트 + 왜 불확실한지 함께.

결정층 지도 (앵커는 편집 시 이동하므로 섹션 주석으로 찾을 것):
- 경로예측 / 공격판별·위협할당
- **수비 need-bound** (grind-window, HQ 생산우선, 못지킬 기지 포기)
- 경제 빌드오더 (07031646r 이식)
- **HQ 래더 + hp-타이브레이크 fund**
- hit&return 회수 (저HP raider rotation)
- **끝내기 + 타깃선정(가치/비용) + anti-trickle**
- 극후반 tiebreak 레이드 (turn-200 판정)
- wave commitment / 잉여 배치·rally·로밍 harass·gather

**③ 설계의도 대조 (INTENT)**
남기고자_하는_기능.md에서 그 동작이:
- **의도된 keep/transform** → 문제는 *튜닝 / 조건 경계* (예: 극후반 tiebreak, hit&return은 사용자 채택)
- **의도에 없는 창발 / 사각** → 문제는 *구조* (배분 얽힘 · 평가 누락)
이 구분이 대처방향의 성격을 결정한다.

**④ 대처방향 (FIX) — 사용자가 "근거 틀렸다"고 판정한 경우에만 낸다**
②는 판정 전까지 **중립 서술만**. 내가 먼저 "이건 버그"로 단정하지 않는다(명백하면 플래그는 함).
사용자 판정 후, "이런 상황(발화 조건)에서는 이렇게" 형태로:
- (a) 원인 **조건을 좁혀서** 제안 — 전역 상수 깎기가 아니라 발화 조건 자체를 손봄
- (b) **정상 케이스를 안 깨는지** 확인 — 그 조건이 이겼던 판에서도 발화하나?
- (c) 상수 하드튜닝보다 **조건 / 구조 수정** 우선

**⑤ 구현 & 정합성 스모크 (승인 후, 빠른 루프)**
사용자가 대처방향을 승인하면:
1. **지정한 파일만** 고친다 (기본 = `redesign/bot.cpp`. 두 파일이 갈려 있으면 어디에 넣을지 확인).
2. `g++ -O2 -std=c++17 redesign/bot.cpp -o bot.exe` 컴파일 (decide()는 무플래그 빌드에만 포함).
3. **한 판 정합성 스모크**: 레퍼리로 1게임 완주 확인 —
   `python Seongho/.../engine/testing-tool-practice.py --seed <s> -l <log> -a bot.exe -b bot.exe`.
   유효 `RESULT`(몰수·WA·TLE 없이 200턴 or 정상 종료)면 통과. 끝.
4. 그리고 **다음 문제 지적**으로 넘어간다.
- **SIM_TEST / OBS_TEST 200턴 매치는 기본 단계에서 뺀다** (느리고 토큰 과다). 단 `step()` /
  `apply_result_block()` 등 **시뮬레이터·월드모델을 건드린 경우에만** SIM/OBS 게이트를 돈다
  (decide()만 고쳤으면 이 게이트는 무의미 — 안 돎).

## 가드레일 (핵심)
- **단일 배틀 = 증거 1건.** 대처방향은 *가설*이지 확정 변경이 아니다. 한 판에 맞춰 상수를 깎지 않는다
  — 벤치는 랜덤시드 양사이드 미러, 오버피팅 금지.
- **facts.md의 "오더 품질 신호"**(순손해 교전·정크무빙·헛발동 후보)는 *결정론적 관찰*일 뿐.
  손해 판정은 맥락(직후 효과·승패 영향)으로. 신호 ≠ 단정.
- **정합성 스모크 ≠ 승률 증명.** 한 판 완주는 "불법수·크래시 없음"만 보증한다. 그 수정이 실제로
  이득인지(승률)는 별개 — 상수를 한 판에 맞춰 깎지 말고, 채택 판정이 필요하면 페어드 대조로.
- ②판단근거 역추적 단계는 **읽기 전용**. 코드 수정은 ④ 승인 뒤 ⑤에서만.
