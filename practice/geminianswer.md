바둑의 예시가 아주 정확합니다! 바둑이나 체스 같은 추상 전략 게임의 AI 프로그래밍(특히 완벽한 정보 하의 턴제 게임)에서 이를 **'단순화(Simplification)'** 또는 **'승률 최적화 지향(Win-probability mapping)'**이라고 부릅니다.

현재 봇의 코드를 보면 평가 함수가 `(myCnt - oppCnt) * W_MAT`으로 **'선형적(Linear)'**입니다. 즉, 1점 이길 때와 20점 이길 때의 1점 가치를 동일하게 계산하죠. 이 경우, 엔진은 100% 확실하고 안전한 +3점 승리보다, 탐색 한계(Horizon) 너머에 변수가 엄청 많지만 당장 +15점을 기대할 수 있는 **'불확실한 도박수(무리수)'**를 선택할 위험이 있습니다.

승리에 초점을 맞추고 '확실한 한 집 반 승리'를 지향하는 굳건한 봇을 만들려면 현재의 Alpha-Beta 엔진 안에서 다음 3가지 방법을 적용할 수 있습니다.

---

### 1. 평가 함수의 비선형화 (Diminishing Returns)

가장 직접적인 방법입니다. 격차가 일정 수준 이상(예: 5점~10점) 벌어지면, **추가로 점수를 내는 것의 가치를 대폭 깎아버리는 것**입니다.

기존의 `matStm()`을 다음과 같이 수정하여, 엔진이 '큰 점수차'보다 '빠르고 안전한 방어'에 연산량을 집중하게 만듭니다.

```cpp
inline int matStm() const {
    int diff = (to_move == 0 ? (myCnt - oppCnt) : (oppCnt - myCnt));

    // 비선형 평가 (승리 지향형 스코어링)
    int abs_diff = std::abs(diff);
    int margin = 5; // 안정권이라고 생각되는 격차 (예: 5칸)

    int score = 0;
    if (abs_diff <= margin) {
        score = abs_diff * W_MAT; // 박빙일 때는 1칸의 가치가 큼
    } else {
        // 이미 margin 이상 이기고/지고 있다면, 추가 1칸의 가치를 1/10로 대폭 줄임
        score = margin * W_MAT + (abs_diff - margin) * (W_MAT / 10);
    }

    return diff > 0 ? score : -score;
}
```

- **효과:** 엔진이 +6점에서 +7점을 만들기 위해 복잡한 수를 두는 것보다, 상대의 반격을 차단해서 현재의 +3점을 +4점으로 '굳히는' 방향의 노드들을 더 높게 평가하게 됩니다.

### 2. 판 정리 인센티브 (Simplification Bonus)

바둑에서 유리한 기사가 가장 많이 하는 행동이 **'교환해서 변수 줄이기(판 닦기)'**입니다. 게임판에 남은 버섯(미지수)이 적을수록 승리는 굳어집니다.

현재 리드하고 있다면, 누가 점수를 내든 상관없이 **빈 공간이 많아지는 것(진행도가 높은 것)** 자체에 가산점을 주고, 지고 있다면 판을 복잡하게 끌고 가도록(진행도가 낮을수록 좋게) 만듭니다.

```cpp
// horizonEval() 등 리프 노드 평가에 적용
inline int horizonEval() const {
    int score = matStm();
    if (wTempo) score += wTempo * scanBestCapture();

    // 현재 남은 총 버섯 수 (혹은 제거된 버섯 수 = myCnt + oppCnt)
    int progress = myCnt + oppCnt;
    int W_SIMPLIFY = 10; // 단순화 가중치 (W_MAT이 100일 때 적당히 작은 값)

    int diff = (to_move == 0 ? (myCnt - oppCnt) : (oppCnt - myCnt));

    if (diff > 0) {
        score += progress * W_SIMPLIFY; // 리드 시: 겜이 많이 진행됐을수록 좋음 (안전함)
    } else if (diff < 0) {
        score -= progress * W_SIMPLIFY; // 뒤쳐질 시: 겜이 많이 진행됐을수록 나쁨 (역전 기회 잃음)
    }

    return score;
}
```

- **효과:** 엔진이 유리할 때는 내 이득을 극대화하기보다, **상대가 점수를 먹더라도 판이 텅텅 비어버리는 안전한 교환**을 선택합니다.

### 3. 과반(승리) 확정 시 최단 경로 지향 (Mate in N)

전체 보드 크기나 초기 버섯 수가 고정되어 있으므로, 한 플레이어가 전체 버섯의 절반 이상을 획득하면 **수학적으로 100% 승리**가 확정됩니다. 이 상태를 감지하면 점수 계산을 멈추고 **가장 빠르게(depth가 적게) 승리하는 길**을 택하게 해야 합니다.

```cpp
int negamax(int depth, int alpha, int beta, int ply, ...) {
    // ... 생략 ...

    // 전체 버섯 수의 과반(예: 초기 버섯이 100개였다면 50개 초과)을 달성했는지 체크
    // (사전에 초기 버섯 개수 TOTAL_MUSHROOMS를 계산해둬야 함)
    if (myCnt > TOTAL_MUSHROOMS / 2) {
        // 내가 무조건 이겼다! 단, 빨리 이기는 것(ply가 작음)을 더 선호
        int mateScore = 500000 - ply * 100;
        return (to_move == 0) ? mateScore : -mateScore;
    }
    if (oppCnt > TOTAL_MUSHROOMS / 2) {
        int mateScore = 500000 - ply * 100;
        return (to_move == 1) ? mateScore : -mateScore;
    }

    // ... 기존 로직 ...
}
```

- **효과:** "상대를 괴롭히면서 20집 이기는 느린 길" 대신, "가장 확실하고 빠르게 항복을 받아내는 길"로 즉각 탐색이 종료됩니다. 탐색 트리가 엄청나게 좁아져서 깊은 곳까지 연산이 가능해지는 덤(Pruning)도 얻습니다.

### 요약: 게임 엔진을 '최상위 바둑기사'처럼 행동하게 하려면?

기존의 MCTS(알파고 방식)는 승률(Win-rate) 자체를 퍼센트로 평가하기 때문에 이 로직이 자연스럽게 탑재되어 있습니다.
하지만 현재 만드신 구조인 **Min-Max(Alpha-Beta)는 태생적으로 '점수 마진(Margin)'을 최적화**하는 맹수가 되기 쉽습니다.

따라서 이 맹수의 목표를 **1) 마진의 비선형화**, **2) 유리할 때 판 비우기(Simplification)** 두 가지 장치로 조율해 주시면, "무리해서 10집 차이 내려다 삐끗해서 지는 봇"에서 **"한 번 유리해지면 질식할 듯 변수를 틀어막아 반 집 차이로 무조건 이기는 봇"**으로 성격이 완전히 진화할 것입니다.

사용자 질문: 게임룰은 다음과 같은데 그걸 참고해서 다시한번 답변해주라. 내 생각엔 3번 전략은 유효성이 조금은 떨어질 것 같긴 하거든

작성자님의 통찰력이 정말 대단하십니다! 룰을 정확하게 간파하셨네요.

말씀하신 대로 **3번 전략(과반수 획득 시 즉시 승리 확정)은 이 게임에서 성립하지 않습니다.**
가장 핵심적인 룰인 **"상대가 이미 점령한 칸(0)을 포함해서 10을 만들면 소유권을 빼앗아 올 수 있다"**는 조항 때문입니다. 내가 100칸 중 80칸을 점령했더라도, 상대가 남은 버섯들을 기가 막히게 조합해서 내 영토 80칸을 통째로 덮어버리는 커다란 직사각형을 만들면 순식간에 역전당할 수 있는 **극강의 '땅따먹기(탈취)' 게임**이기 때문입니다.

따라서 룰의 특수성을 완벽히 반영하여 **승리에 쐐기를 박는(격차보다 승률을 높이는) 맞춤형 전략**으로 다시 정리해 드리겠습니다.

### 1. 비선형 평가 (안전제일주의) - 여전히 유효하고 가장 중요함!

탈취가 가능하기 때문에 오히려 **'격차 최대화(탐욕)'를 억제하는 비선형 평가가 절대적으로 필요**합니다.
엔진이 선형 평가를 쓰면 "+30칸을 먹을 수 있지만 다음 턴에 역전당할 리스크가 있는 수"와 "+5칸을 먹고 판을 굳히는 수" 중 전자를 택하다가 탐색 깊이(Horizon) 밖에서 카운터 펀치를 맞고 질문할 수 있습니다.

따라서 **"이기고 있을 때는 1점의 가치를 대폭 낮춰서, 무리한 대박보다는 확실한 소박을 택하게"** 만들어야 합니다.

```cpp
inline int matStm() const {
    int diff = myCnt - oppCnt;
    int sign = (to_move == 0) ? 1 : -1;
    diff *= sign; // 현재 턴을 두는 플레이어 관점에서의 점수 차이

    int abs_diff = std::abs(diff);
    int score = 0;

    // 마진(예: 10칸) 이내일 때는 치열하게 1칸의 가치를 100으로 침
    if (abs_diff <= 10) {
        score = abs_diff * W_MAT;
    } else {
        // 이미 10칸 이상 이기고(지방) 있다면, 추가 점수의 가치를 10(W_MAT의 1/10)으로 깎음
        // 즉, 무리해서 큰 땅을 먹는 것보다 '안전한' 진행을 선호하게 됨
        score = (10 * W_MAT) + (abs_diff - 10) * (W_MAT / 10);
    }

    return diff > 0 ? score : -score;
}
```

### 2. 소거(판 비우기) 인센티브 - 0이 아닌 버섯 없애기

바둑의 '판 닦기' 전략을 이 룰에 맞게 적용하는 방법입니다.
이 게임에서 0(빈칸)은 계속 주인이 바뀔 수 있지만, **한 번 0이 된 칸은 다시 숫자로 돌아오지 않습니다.** 즉, **'보드 위에 남은 숫자가 0이 아닌 버섯의 개수'는 무조건 줄어들기만 하는 비가역적 자원**입니다.

내가 유리한 상황이라면 상대가 역전할 '재료(숫자 1~9 버섯)'를 없애버리는 것이 최고의 방어입니다.

```cpp
inline int horizonEval() const {
    int score = matStm();
    if (wTempo) score += wTempo * scanBestCapture();

    // 현재 보드에 남은 '0이 아닌 진짜 버섯'의 개수를 추정
    // (myCnt + oppCnt는 전체 보드에서 0이 된 칸의 총합이므로, 이것이 클수록 남은 버섯은 적음)
    int clearedCells = myCnt + oppCnt;

    // 단순화 가중치 (점수 가중치인 100보다는 작게 주어 주객전도를 막음)
    const int W_SIMPLIFY = 15;

    int diff = (to_move == 0 ? (myCnt - oppCnt) : (oppCnt - myCnt));

    if (diff > 0) {
        // 리드 중: 빈칸이 많아질수록(진행될수록) 굳히기에 들어가므로 가산점 부여
        score += clearedCells * W_SIMPLIFY;
    } else if (diff < 0) {
        // 뒤쳐지는 중: 빈칸이 많아질수록 역전 기회가 사라지므로 감점 (판을 어지럽게 유지하도록 유도)
        score -= clearedCells * W_SIMPLIFY;
    }

    return score;
}
```

### 3. 진정한 'Mate(승리 확정)' 감지 - 잔여 합계 < 10

과반수를 먹는다고 이기는 것은 아니지만, **"보드 전체에 남은 버섯의 숫자 합이 10 미만"**이 되면 그 누구도 더 이상 수를 둘 수 없습니다! (유효 조건 1: 합이 10이어야 함).
또는 더 간단하게 보드 전체에 남은 **버섯(0이 아닌 칸)의 개수 자체가 극히 적어질 때**를 이용할 수 있습니다.

탐색 과정에서 이 조건을 빠르게 체크하여 게임 끝까지 연산해버리면 엄청난 효율을 낼 수 있습니다.

```cpp
// negamax 함수나 평가 함수 내에서 적용 가능
int getRemainingSum() const {
    int sum = 0;
    for (int r = 0; r < R; r++) {
        for (int c = 0; c < C; c++) {
            sum += num[r][c]; // 0인 칸은 더해도 0
        }
    }
    return sum;
}

// negamax 안에서:
if (getRemainingSum() < 10) {
    // 더 이상 양쪽 모두 10을 만들 수 없음 -> 즉시 게임 종료 상태
    // 현재 점수에 따라 +INF(승리) 또는 -INF(패배) 반환
    int diff = (to_move == 0 ? (myCnt - oppCnt) : (oppCnt - myCnt));
    if (diff > 0) return 500000 - ply;  // 빨리 이길수록 좋음
    if (diff < 0) return -500000 + ply; // 늦게 질수록 좋음
    return 0; // 무승부
}
```
