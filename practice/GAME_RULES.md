# 버섯 밭 점령 게임 — 규칙 & 구현 가이드

> NYPC 2026 / "10 만들기" 류 인터랙티브 대전 봇.
> 이 문서는 **전략이 아니라 규칙과 규칙 준수 구현**만 다룬다.
> 기준 코드: [sampleCode/sample_code.py](sampleCode/sample_code.py), [sampleCode/sample_code.cpp](sampleCode/sample_code.cpp)

---

## 1. 게임 개요

- 두 플레이어(예티 / 핑크빈)가 **번갈아 턴**을 진행한다.
- 각 턴에 숫자 버섯 밭에서 **직사각형 하나**를 선택한다.
- 선택 영역 안 숫자 **합이 정확히 10**이면 그 영역을 점령(버섯 제거)한다.
- **더 많은 칸을 점령한 쪽이 승리.**

---

## 2. 보드 사양

| 항목 | 값 |
|------|-----|
| 행(row) 수 | 10 (`r` = 0 ~ 9) |
| 열(col) 수 | 17 (`c` = 0 ~ 16) |
| 좌상단 좌표 | `(r, c) = (0, 0)` |
| 우하단 좌표 | `(r, c) = (9, 16)` |
| 각 칸 숫자 | 1 ~ 9 정수 (균등·독립 분포) |
| 제거된 칸 | 0 (버섯 없음) |

- 좌표는 항상 **(행 r, 열 c)** 순서.
- `INIT`은 10개의 문자열을 주고, 각 문자열은 17자리 숫자다. (보드 = 10×17)

---

## 3. 유효한 수(직사각형)의 조건

직사각형 `(r1, c1) ~ (r2, c2)`가 **유효**하려면 아래 **모두** 만족해야 한다.

1. **합 = 10**: 영역 내부 칸들의 숫자 합이 정확히 10.
   - 제거된 칸(0)은 합에 기여하지 않는다. 즉 **남아있는 버섯 숫자들의 합**이 10이어야 한다.
2. **네 변 각각에 버섯 인접**: 직사각형의 위/아래/왼쪽/오른쪽 변마다 **0이 아닌 칸이 최소 하나씩** 닿아 있어야 한다.
   - 위 변: `r == r1` 행에 버섯 ≥ 1
   - 아래 변: `r == r2` 행에 버섯 ≥ 1
   - 왼 변: `c == c1` 열에 버섯 ≥ 1
   - 오른 변: `c == c2` 열에 버섯 ≥ 1
   - → 테두리에 빈(0) 줄이 패딩처럼 붙는 것을 금지. 같은 영역을 여러 좌표로 표현하지 못하게 하는 "딱 맞춤" 조건.

> 코드상 검증: `is_valid` / `isValid` 함수가 위 두 조건을 그대로 체크한다.
> 참고: 한 칸 숫자는 최대 9이므로 **1×1 직사각형은 절대 유효하지 않다**(합 10 불가). 최소 2칸 이상.

### 점령과 소유권 (중요한 구분)

- 영역이 유효하면 그 칸들을 점령하고 **버섯을 제거(0으로)** 한다.
- 영역 안에 **상대가 이미 점령한 칸(이미 0인 칸)** 이 포함돼 있으면, 그 칸의 **소유권도 빼앗는다**.
- 따라서 보드에는 **두 개의 레이어**가 있다:
  - **숫자 레이어**: 버섯 숫자(제거되면 0) — *유효성 판정에 필요한 전부*.
  - **소유권 레이어**: 각 칸을 누가 점령했는지 — *점수 계산에만 필요*.
- ⚠️ **샘플 코드는 숫자 레이어만 관리**하고 소유권은 추적하지 않는다.
  규칙상 "유효한 수를 출력"하는 데는 숫자 레이어만 있으면 충분하기 때문.
  (점수를 직접 계산하려면 소유권 레이어를 따로 둬야 함 — 이건 전략 영역.)

## 4. 패스 & 게임 종료

- **패스**: 선택 가능한 영역이 없거나 일부러 넘기고 싶을 때 가능. 출력은 `-1 -1 -1 -1`.
- **종료**: 두 플레이어가 **연속으로 패스**하면 게임 종료.
  - 종료 판정은 **심판(judge)** 이 한다. 봇은 그 결과로 `FINISH` 명령을 받을 뿐이다.
  - 즉, 봇이 직접 연속 패스를 셀 필요는 없다(전략용으로 추적은 가능).
- **승패**: 종료 시점에 **점령 칸 수가 많은 쪽 승리.**

## 5. I/O 프로토콜

프로그램은 **한 줄씩** 입력을 받아 명령별로 동작한다. 출력이 필요한 명령은 표의 **출력** 열에 표기.

| 커맨드 | 입력 형식 | 출력 | 설명 |
|--------|-----------|------|------|
| `READY` | `READY (FIRST\|SECOND)` | **`OK`** | 선/후공 통지. **3초 이내** `OK` 출력. |
| `INIT` | `INIT s1 s2 ... s10` | 없음 | 보드 초기화. `s_i`는 17자리 숫자 문자열. |
| `TIME` | `TIME t1 t2` | **`r1 c1 r2 c2`** | 내 턴. `t1`=내 남은 시간, `t2`=상대 남은 시간(ms). 둘 수를 출력. |
| `OPP` | `OPP r1 c1 r2 c2 t` | 없음 | 상대 수 통지. `t`=상대가 쓴 시간. 패스면 `-1 -1 -1 -1`. 보드에 반영. |
| `FINISH` | `FINISH` | 없음 | 게임 종료. 정상 종료할 것. |

- `OPP`의 인자는 문서상 `x1 y1 x2 y2`로 쓰이기도 하지만 실제 의미는 `r1 c1 r2 c2`다.
- `TIME`에서 패스하려면 `-1 -1 -1 -1` 출력.

### 출력 좌표 제약

```
-1 ≤ r1 ≤ r2 ≤ 9
-1 ≤ c1 ≤ c2 ≤ 16
```

- 패스: `r1 = c1 = r2 = c2 = -1`.
- `r1 ≤ r2`, `c1 ≤ c2` 반드시 지킬 것(좌상단 ≤ 우하단).

---

## 6. 시간 관리

- 게임 시간 `t1, t2`의 시작값은 각각 **10000 (= 10초, 단위 ms)**.
- 이 10초는 **게임 전체에 대한 누적 시간**이며, `READY`의 3초와는 **별개**다.
- 초과 시 TLE / 실격 위험 → 턴당 시간 예산을 관리.

## 7. 코드 구현 시 반드시 지켜야 할 것 (체크리스트)

규칙 준수에 직접 영향을 주는 항목들:

- [ ] **모든 출력 뒤 즉시 flush.** flush 안 하면 출력이 안 나가 TLE.
  - Python: `print(*ret, flush=True)`
  - C++: `cout << ... << endl;` (또는 `"\n"` 후 `cout.flush()`)
- [ ] **`READY`에 `OK` 출력** (3초 이내). 안 하면 시작 자체가 안 됨.
- [ ] **보드 동기화 유지**: 유효성 판정은 *현재* 보드 상태에 의존한다.
  - 내 수: `TIME` 처리 후 내가 둔 영역을 0으로 반영.
  - 상대 수: `OPP` 받을 때마다 상대 영역을 0으로 반영.
  - → 둘 다 빠뜨리면 이후 유효성 판정이 틀어진다.
- [ ] **출력은 항상 유효한 수이거나 패스(`-1 -1 -1 -1`).** 유효하지 않은 수를 내면 실격/패배 위험.
  - 직접 만든 수는 출력 전 `is_valid`로 검증하는 습관을 권장.
- [ ] **좌표 제약**(`r1≤r2`, `c1≤c2`, 범위) 준수.
- [ ] `INIT` 파싱: 문자 → 숫자 변환(`c - '0'` / `int`)을 행마다 정확히.
- [ ] `FINISH` 시 루프 탈출 후 **정상 종료**.

## 8. 샘플 코드 구조 — 어디를 구현하나

I/O·보드 관리·유효성 검증은 이미 완성돼 있다. **내가 채울 곳은 단 하나:**

| 언어 | 구현 함수 | 위치 |
|------|-----------|------|
| Python | `Game.calculate_move(self, my_time, opp_time)` | [sample_code.py:35](sampleCode/sample_code.py#L35) |
| C++ | `Game::calculateMove(int myTime, int oppTime)` | [sample_code.cpp:51](sampleCode/sample_code.cpp#L51) |

- 반환: 유효한 `(r1, c1, r2, c2)` 또는 패스 `(-1, -1, -1, -1)`.
- 함수 밖(`update_move`, `is_valid`, `main`, I/O 루프)은 그대로 두면 됨.
- 현재 샘플 구현: 가로로 인접한 두 칸만 훑어 합 10이면 반환, 없으면 패스 (placeholder).

이미 제공되는 유틸:
- `is_valid / isValid(r1,c1,r2,c2)` → 위 §3 두 조건 검증. **직접 만든 수 검증에 재사용 가능.**
- `update_move / updateMove(...)` → 영역을 0으로 만들고 패스 플래그 갱신.

## 9. 로컬 테스트 (testing_tool.py)

`testing_tool.py`와 같은 폴더에 **`setting.ini`** 작성:

```ini
INPUT=./input.txt
LOG=./log.txt
EXEC1=./Main.exe
EXEC2=python3 main.py --test
```

| 키 | 의미 |
|----|------|
| `INPUT` | 보드 초기 상태 파일 (10줄, 각 줄 17자리 숫자) |
| `LOG` | 로그 출력 경로 |
| `EXEC1` | **선공** 프로그램 실행 커맨드 |
| `EXEC2` | **후공** 프로그램 실행 커맨드 |

### 입력 파일 형식

10줄 × 각 줄 17개의 1~9 숫자. 예:

```
52466443835422223
13254826938785712
87598398564241564
72722154162442227
43968227685821641
27727492381231148
56138649164249527
36281415328768234
62682694189422313
62269566965435457
```

### 로그 해석

| 로그 라인 | 의미 |
|-----------|------|
| `INIT s1 ... s10` | 초기 보드 |
| `<FIRST/SECOND> r1 c1 r2 c2 time` | 선/후공이 둔 수 + 사용 시간(ms) |
| `FINISH` | 정상 종료 |
| `SCORE<FIRST/SECOND> score` | 선/후공 최종 점수 |
| `ABORT <0/1> reason` | 선공(0)/후공(1) 비정상 종료 + 사유 |

> 채점 서버는 testing_tool과 **다르게 구현**돼 있다. 로컬 정상 동작이 서버 정상 동작을 보장하지 않음.
> testing_tool 수정은 자유지만, 수정본·로그를 **팀원 외 공유 금지**.
