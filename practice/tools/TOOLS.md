## 0. 레이어 구분 (모든 도구의 전제)

보드는 두 레이어로 본다.

| 레이어 | 의미 | 누가 쓰나 |
|--------|------|-----------|
| **숫자 레이어** `num[R][C]` | 버섯 숫자 1~9, 제거되면 0 | **수 생성·유효성 판정에 필요한 전부** |
| **소유권 레이어** `owner[R][C]` | 각 칸을 누가 점령했는지 | **점수 계산에만** 필요 |

- `R = 10`(행), `C = 17`(열). 좌표는 항상 `(행 r, 열 c)`.
- **유효한 수는 숫자 레이어만의 함수다.** 소유권이 바뀌어도(이미 0인 칸 재점령) 유효수 집합은 변하지 않는다.
- 따라서 첫 도구인 **수 생성(T4)** 은 숫자 레이어만으로 완결된다. 소유권은 점수 도구(T6)에서 도입.

## 2. [T4 상세] 수 생성 — 행밴드 압축

### 2.1 정의

- `Move = {r1, c1, r2, c2}` (좌상단 ≤ 우하단). 정규 인코딩 `encMove`로 집합/정렬·비교.
- 도구는 **현재 보드의 모든 유효 직사각형 집합**을 항상 최신 상태로 들고 있는다.
- **유효 조건 2개** (규칙 §3 직역):
  1. 영역 내 남은 숫자 합 = **10** (0인 칸은 합에 기여 안 함)
  2. **네 변 각각에 버섯 인접**: 위 변(`r1`행)·아래 변(`r2`행)·왼 변(`c1`열)·오른 변(`c2`열) 각각에 0이 아닌 칸 ≥ 1
- 한 칸 최대 9 → **1×1은 절대 유효하지 않음**(합 10 불가). 최소 2칸.

### 2.2 핵심 루틴 — 행밴드 압축 + 1D 부분합  `scanBandRow`

"합=목표인 모든 직사각형 열거"는 **LeetCode 1074 계열**. 위/아래 행 `(r1, r2)`를 고정하고
세로로 압축하면 17칸짜리 1D 열-합 문제로 줄어든다.

- 한 밴드 `[r1,r2]`에서 `colSum[c]`(열 숫자합)·`colCnt[c]`(열 버섯 수)를 누적.
- 좌변 `c1` 고정 후 우변 `c2`를 늘리며 부분합 `s` 누적:
  - **`s > 10`이면 즉시 break** ← ★ 범위 제한은 거리가 아니라 **합**이다 ★
  - `s == 10 && colCnt[c2]>0 && topP && botP` 이면 유효수 → 추가
    (`topP`/`botP` = `[c1,c2]` 안에서 위/아래 행에 버섯 존재, `colCnt`로 좌/우 변 충족)
- 모든 값 ≥ 0이라 부분합이 단조 증가 → break가 정확. 0(제거칸)과 네 변 조건은 인라인 처리.
- 복잡도 **O(R²·C)** 수준. (브루트포스 O(R²·C²) 대비. 10×17에선 첫 수가 어느 방식이든 <1ms라
  속도 자체보다 **이 루틴을 모드 A·B가 공유**하는 점이 핵심.)

### 2.3 모드 A — 전체 스캔 (오라클)  `fullScan`

모든 밴드 `(r1,r2)`에 대해 `scanBandRow`. 정답 기준선이자 모드 B의 검증 오라클.
첫 수(초기화)에서 전체 유효수를 열거해 저장하는 데 사용.

### 2.4 모드 B — 합기준 국소 증분 (채택)  `IncrementalMoveGen::applyMove`

첫 수의 저장 집합을, 매 수마다 **점령된 칸 집합 D**(숫자 → 0)만으로 국소 갱신한다.
내 수(`TIME`)·상대 수(`OPP`) 둘 다 보드를 바꾸므로 양쪽에 적용.

1. **D 수집·제거**: 적용 직사각형 안에서 *현재 비영인* 칸만 D로 모아 0으로. 행 범위 `[dRmin,dRmax]` 기록.
   - D가 비면(소유권만 변경) **집합 불변** → 즉시 종료.
2. **생존수 제거**: D 칸을 하나라도 포함한 기존 수는 버섯을 잃어 무효 → 삭제.
   - ★ **반드시 신생수 추가보다 먼저** ★ (신생수도 D를 포함하므로 순서가 뒤집히면 같이 지워짐)
3. **신생수 재유도**: D를 가로지르는 밴드를 **세로·가로 모두 제거영역 기반으로 끊어** 스캔,
   **제거칸을 실제 품은 박스(`remSum>0`)만** 삽입.
   - 세로 `br1 ≤ dRmax && br2 ≥ dRmin`, 가로 `c1 ≤ dCmax && c2 ≥ dCmin`, + `s>10` break + `remSum>0`.
   - `remSum>0`로 거르므로 **신생수만** 삽입(생존수는 2단계에서 안 지워져 이미 집합에 있음).
   - **4방향 적응형 앵커**: 밴드의 열 합은 앵커마다 다시 쌓이므로(재누적), 제거박스에 **가까운
     모서리**(좌상/우상/좌하/우하)에 앵커를 맞춰 재누적 횟수를 최소화(`rowFlip`/`colFlip`).
     앵커(시작 변)만 박스 가까이로 묶이고 반대편 inner 스캔은 끝까지 — *결과 집합은 불변*.

**왜 거리(반경)로 제한하면 안 되나 — 비국소성:** 신생수는 사라진 칸을 *포함*만 하면 되고,
내부에 이미 0인 칸을 잔뜩 품은 채 멀리 뻗을 수 있다. 예 `3 0 0 0 0 0 0 7`(폭 8·합 10):
중간이 전부 0이라 부분합이 10을 *안 넘다가* 끝에서 딱 10. "주변 k칸" 고정 반경은 이를 놓친다.
→ **국소성은 칸-공간이 아니라 값-공간(합 ≤ 10)에서 성립.** 신생수의 *직전* 합 ∈ **[11, 20]**
(방금 둔 수의 제거값 총합 = 10 → 신생수가 품은 제거값 v ≤ 10).

**기각된 대안 — near-miss(합 11~20) 사전 저장:** 신생수를 빨리 잡으려 합 11~20 직사각형을
미리 들고 있으려는 발상. (i) 합 10보다 후보가 훨씬 많고 (ii) 그 집합도 매 수 생성·소멸해
같은 증분 문제를 **재귀적으로** 떠안음 → 전체 재스캔 대비 이득 없음. **폐기.** 정답은 "저장"이
아니라 위 3의 "제거영역 컷 + `remSum>0` 재유도".

### 2.5 검증 결과 (모드 B 채택의 게이트) ✅

[tools/moveGen/moveGen.cpp](moveGen/moveGen.cpp)가 **차분 검증 하니스**를 포함한다.

- **방법**: 무작위·적대적(작은 값/0-복도) 보드에서 임의 수 시퀀스(유효수 70% / 임의 직사각형
  제거 20% / 단일칸·소유권 경로 10%)를 진행하며, **매 수마다 "모드 B 집합 == 모드 A 집합"** 을
  순서 무관 비교. 불일치 시 보드·diff 덤프 후 abort. `fullScan == bruteForce`(isValid 4중 루프)도
  주기적 교차검증.
- **결과**: 9시드 × 20만 = **180만 포지션 불일치 0건**, 오라클 교차검증 통과
  (4방향 적응형 앵커 적용 후 재검증).
- **네거티브 컨트롤**(하니스 검사력 + 네 분기 도달 입증): 네 방향 컷(위/아래/왼/오른)을 각각
  한 칸 좁히면 즉시 불일치 포착(abort) — 각 경계가 정확하고 **4방향 분기 모두 실제로 실행됨**을 입증.

빌드·실행:
```
cd tools/moveGen
g++ -O2 -std=c++17 moveGen.cpp -o moveGen.exe   # (MSYS2면 PATH에 mingw64/bin 추가)
./moveGen.exe [seed] [target_positions]          # 통과 시 "[OK] ... 전부 일치"
```

## 3. 나머지 도구 간략 스펙 (후속 단계에서 구현·검증)

- **T1 보드·상태 표현** — `struct State { int num[R][C]; int owner[R][C]; int myCnt, oppCnt; }`.
  `owner`는 `num!=0`이면 없음(-1), `num==0`이면 0(나)/1(상대).
- **T2 보드 초기화** — `INIT s1..s10` 의 각 17자리 문자열을 `num[r][c] = s[c]-'0'` 로. `owner` 전부 -1.
- **T3 유효성 검사** — `isValid(num, r1,c1,r2,c2)` (이미 구현). §2.1 두 조건. 직접 만든 수 검증·테스트에 재사용.
- **T5 수 적용** — `playMove(State&, move, mover)`: 영역 내 버섯 제거(0) + 소유권 부여,
  *이미 0인 칸*은 소유권만 탈취. (데모 [main.cpp:64](../level1Demo/main.cpp#L64) 참고.)
  ※ 수 생성과 연동: 적용 후 모드 B로 유효수 집합 갱신.
- **T6 점수 계산** — `owner`에서 0/1 칸 수를 세어 (내 점수, 상대 점수). 종료 시 많은 쪽 승.
- **T7 보조 조회** — 남은 버섯 수(`num!=0` 카운트), 유효수 유무로 패스 판정 등.

## 4. 구현 순서 로드맵

1. **T4 수 생성** — 행밴드 압축(모드 A) + 합기준 국소 증분(모드 B) + 차분 검증.  **← 완료 ✅**
2. **T5 수 적용 · 보드 동기화** — 내 수/상대 수를 보드에 반영하고 T4 집합과 연동.
3. **T1·T6 소유권·점수** — 소유권 레이어 도입, 점수 집계.
4. **T2 · I/O 프로토콜 결선** — `READY/INIT/TIME/OPP/FINISH` 루프와 묶어 동작하는 봇.
5. *(이후, 본 문서 범위 밖)* **전략** — 수 평가·트리탐색·시간관리.
