# nodeGen — 노드 생성 (node generation)

NYPC 2026 "버섯 밭 점령 게임" 봇의 기반 도구. 본질적으로 탐색 트리의 **노드 생성기**다:
**현재 보드의 모든 유효한 직사각형(수) 집합**을 구하고(매 수마다 최신 유지), 각 수(= 자식 노드)에
**그 수가 만드는 점수 변화량 Δ(cap, steal)** 를 함께 붙여 낸다.

- 두 역할은 레이어가 다르다: **수의 존재(유효성) = `num` 레이어만의 함수**(§1~§4, 검증된 코어),
  **노드의 값 Δ = `owner` 레이어 의존 주석 한 겹**(§4.5, 생성 시점에만 산출·캐싱 안 함).
- 구현·검증 코드: [nodeGen.cpp](nodeGen.cpp)
- 상위 규칙 문서: [../../GAME_RULES.md](../../GAME_RULES.md) §3
- 도구 카탈로그 내 위치(T4): [../../TOOLS.md](../../TOOLS.md)

## 1. 무엇을 푸는가

보드는 `R=10` 행 × `C=17` 열, 각 칸은 버섯 숫자 `1~9`, 제거되면 `0`.
**유효한 수**(직사각형 `(r1,c1)-(r2,c2)`)의 조건 2개 (규칙 §3):

1. **합 = 10** — 영역 내 남은 숫자의 합이 정확히 10 (0인 칸은 기여 안 함).
2. **네 변에 버섯 인접** — 위 변(`r1`행)·아래 변(`r2`행)·왼 변(`c1`열)·오른 변(`c2`열)
   각각에 0이 아닌 칸이 ≥ 1.

> 한 칸 최대 9 → **1×1은 절대 유효하지 않음**(합 10 불가). 최소 2칸.
> 유효성은 **숫자 레이어만의 함수** — 소유권(누가 점령했는지)은 *수의 존재*와 무관(노드의 *값* Δ에만 필요).

## 3. 핵심 알고리즘 — 행밴드 압축 + 1D 부분합

"합 = 목표인 모든 직사각형 열거"는 위/아래 행 `(r1,r2)`를 고정해 세로로 압축하면
17칸짜리 **1D 열-합** 문제로 줄어든다 (LeetCode 1074 계열).

`scanBandRow`(밴드 `[r1,r2]`, 누적된 `colSum`/`colCnt`):

```
좌변 c1 고정 (colCnt[c1] > 0 이어야 함)
  우변 c2 를 늘리며 부분합 s 누적:
    s > 10  → 즉시 break          ← ★ 범위 제한은 "거리"가 아니라 "합" ★
    s == 10 && colCnt[c2]>0 && 위변·아래변 버섯 존재 → 유효수
```

모든 값 ≥ 0이라 부분합이 단조 증가 → `s>10` break가 정확. 복잡도 약 **O(R²·C)**.

- **모드 A `fullScan`**: 모든 밴드에 `scanBandRow`. 첫 수에서 전체 유효수를 저장.

## 4. 모드 B — 합기준 국소 증분 (`applyMove`)

첫 수의 저장 집합을, 매 수마다 **점령된 칸 집합 D**(숫자 → 0)만으로 국소 갱신한다.
(내 수·상대 수 둘 다 보드를 바꾸므로 양쪽에 적용. 적용 수가 합=10일 필요는 없음 —
로직은 *제거된 칸*에만 의존.)

1. **D 수집·제거**: 적용 영역 안의 *현재 비영* 칸만 0으로. 제거칸 bbox `[dRmin,dRmax]×[dCmin,dCmax]` 기록.
   D가 비면(소유권만 변경) **집합 불변** → 종료.
2. **생존수 제거**: D 칸을 포함한 기존 수는 버섯을 잃어 무효 → 삭제.
   ★ **신생수 추가보다 먼저** ★ (신생수도 D를 포함 → 순서가 뒤집히면 같이 지워짐).
3. **신생수 재유도**: D를 가로지르는 밴드를 **세로·가로 모두 제거영역 기반으로 끊어** 스캔하고,
   **제거칸을 실제로 품은 박스(`remSum>0`)만** 삽입한다.
   - 세로: `br1 ≤ dRmax && br2 ≥ dRmin` (밴드가 D 행을 가로지름)
   - 가로: `c1 ≤ dCmax && c2 ≥ dCmin` + `s>10` break + `remSum>0` 게이트
   - `remSum>0`로 거르므로 **신생수만** 삽입 (생존수는 2단계에서 안 지워져 이미 집합에 있음 → 재삽입 불필요).

### 4방향 적응형 앵커 (재누적 최소화)

밴드를 만들려면 그 밴드 행들의 **열 합을 매 앵커마다 다시 쌓는다(재누적)**. 항상 왼쪽위 앵커로
아래·오른쪽으로만 뻗으면, 제거박스가 **우하단**에 가까울 때 앵커 범위(`br1∈[0,dRmax]`,
`c1∈[0,dCmax]`)가 거의 보드 전체 → 재누적 최대. (예: 바닥 한 줄 제거 시 위쪽 앵커 55행 vs 아래쪽 19행.)

→ 제거박스에 **가까운 모서리에 앵커**를 맞춘다. `rowFlip`/`colFlip` (outer 반복수가 적은 쪽):
| 박스 위치 | 앵커 | 뻗는 방향 |
|---|---|---|
| 좌상단 | 좌상단 | ↘ (br1↓, c1→) |
| 우상단 | 우상단 | ↙ |
| 좌하단 | 좌하단 | ↗ |
| 우하단 | 우하단 | ↖ (br2↑, c2←) |

- **앵커(시작 변)만 박스 가까이로 묶임** — 반대편으로 뻗는 inner 스캔은 (0,0)/(R-1,C-1)까지 그대로
  감(멀리 뻗는 와이드/톨 신생수 포함). 즉 *스캔/신생수 집합은 불변*, **재누적 횟수만 감소**.
- 방향이 달라도 같은 네 컷의 대칭 열거라 **결과 동일**(반사·복사 없이 실좌표 그대로 `encMove`).

### 왜 "거리 기반 국소"는 틀리나 (비국소성)

신생수는 사라진 칸을 *포함*만 하면 되고, 내부에 이미 0인 칸을 잔뜩 품은 채 멀리 뻗을 수 있다:

```
3 0 0 0 0 0 0 7      → 폭 8칸, 합 10 (중간이 0이라 부분합이 10을 안 넘다 끝에서 딱 10)
```

"사라진 칸 주변 k칸"이라는 **고정 반경은 이런 와이드 신생수를 놓친다.**
→ **국소성은 칸-공간이 아니라 값-공간(합 ≤ 10)에서 성립.** 그래서 범위 제한 기준이 `s>10`.
신생수의 *직전* 합 ∈ **[11, 20]** (방금 둔 수의 제거값 총합 = 10 → 품은 제거값 v ≤ 10).

### 기각된 대안 — near-miss(합 11~20) 사전 저장

신생수를 빨리 잡으려 합 11~20 직사각형을 미리 보관하는 발상: (i) 합 10보다 후보가 훨씬 많고,
(ii) 그 집합도 매 수 생성·소멸해 같은 증분 문제를 **재귀적으로** 떠안음 → 전체 재스캔 대비
이득 없음. **폐기.** 정답은 "저장"이 아니라 위 3의 "제거영역 컷 + `remSum>0` 재유도".

## 4.5 노드 주석 — 점수 변화량 Δ (cap, steal)

한 수가 만드는 점수 변화 = `cap`(새로 점령하는 버섯 칸) + `steal`(이미 0이며 *상대* 소유인 칸 탈취).
- mover 점수 `+= cap + steal`, 상대 점수 `-= steal` → **margin Δ = cap + 2·steal** (탈취는 나 +1·상대 −1이라 2배).
- 무브 평가의 맹점: "점령 칸 수(cap)"만 보면 탈취 가치를 놓친다.

**자료구조 = 별도 구조 없음.** 밴드 스캔이 이미 `colSum`/`colCnt`를 누적하니(`colCnt` 러닝합 = cap),
`colOpp[c]`(밴드 내 c열에서 `num==0 && owner==상대`인 칸 수) 누적기 **하나(길이 17)** 만 평행하게 더하면
우변 확장 루프에서 `steal` 러닝합이 각 노드마다 O(1)로 따라온다 — `fullScanNodes`가 이걸 한다.

**Δ는 생성 시점 주석 — 캐싱하지 않는다.** 모드 B는 `num` 불변(소유권만 바뀐 탈취)이면 집합을 안 건드리는데,
그 칸을 품은 수의 `steal`은 바뀐다 → 저장하면 stale. 탐색은 노드를 매 노드 새로 생성하므로(엔진 `genMoves`)
Δ를 그때 재계산하면 항상 최신이고 staleness 함정을 피한다.

> summed-area table(2D 프리픽스 합)은 임의 직사각형 Δ를 O(1)로 주는 교과서적 대안이나, 질의 대상이
> 생성기가 이미 만든 후보 수라 스캔-내장이 더 싸고 테이블 2개를 매 수 재구축할 필요도 없어 기각.

## 5. 검증 (채택의 게이트) ✅

`main`이 **차분 검증 하니스**다. (유효수 집합 + 노드 Δ 둘 다 검증)

- **방법**: 무작위·적대적(작은 값/0-복도) `num` 보드 **+ 무작위로 갱신되는 `owner` 레이어**에서 임의 수
  시퀀스(유효수 70% / 임의 직사각형 제거 20% / 단일칸·소유권 경로 10%)를 진행하며 **매 수마다**:
  1. **"모드 B 집합 == 모드 A 집합"** 순서 무관 비교 (유효수 코어). `fullScan == bruteForce`도 주기적 교차검증.
  2. **"`fullScanNodes` 수집합 == 모드 A 집합"** (주석 스캔이 같은 수를 찾는가).
  3. **"노드별 Δ(cap,steal) == `scoreDeltaOracle`"** (= `playMove` 점수규칙). `mover`는 ply마다 교대.
  불일치 시 보드·diff 덤프 후 abort.
- **결과**: 9시드 × 20만 = **180만 포지션 불일치 0건** (유효수 집합 + 노드 Δ 모두), 오라클 교차검증 통과.
- **네거티브 컨트롤**:
  - **Δ**: `-DNODEGEN_NEG_STEAL`로 `steal`을 0으로 주입해 빌드 → 탈취가 처음 생기는 수에서 즉시
    `[NODE-DELTA-MISMATCH]` abort (하니스가 Δ 오류를 실제로 잡음을 입증).
  - **유효수 집합**(기존): 각 방향 컷을 한 칸 좁히면 즉시 불일치 포착 — 거리 기반 국소가 틀림을, 네 방향
    적응형 앵커 분기가 모두 실행됨을 입증.

## 6. 빌드 · 실행

```sh
cd tools/nodeGen
# MSYS2 g++ 사용 시 하위 프로세스 DLL 로드를 위해 PATH에 mingw64/bin 추가
export PATH="/c/msys64/mingw64/bin:$PATH"
g++ -O2 -std=c++17 nodeGen.cpp -o nodeGen.exe

./nodeGen.exe                 # 기본 seed=0xC0FFEE, 150000 포지션
./nodeGen.exe 42 200000       # seed=42, 200000 포지션

# 네거티브 컨트롤(Δ 검사력): 아래 빌드는 즉시 abort 해야 정상
g++ -O2 -std=c++17 -DNODEGEN_NEG_STEAL nodeGen.cpp -o nodeGen_neg.exe && ./nodeGen_neg.exe
```

통과 시 `stderr`에 `[OK] ... 전부 일치` 출력. 불일치 시 `[MISMATCH]`/`[ORACLE-BUG]`/
`[NODE-SET-MISMATCH]`/`[NODE-DELTA-MISMATCH]`로 보드·diff를 덤프하고 비정상 종료한다.

## 8. 봇 연동 시 사용법 (다음 단계 예고)

- `INIT` 직후: `IncrementalNodeGen inc; inc.init(board);` 로 첫 수 집합 저장.
- 내 수/상대 수가 정해질 때마다: `inc.applyMove(r1,c1,r2,c2);` 로 보드·집합 동시 갱신 (소유권 레이어도 함께 유지).
- 내 턴: `inc.moves`가 비면 패스(`-1 -1 -1 -1`), 아니면 그중에서 한 수 선택(선택 로직 = 전략, 범위 밖).
- 탐색·평가: 노드를 생성할 때 `fullScanNodes(num, owner, mover, ...)`로 각 후보의 Δ(cap,steal)를 함께 얻어
  무브 오더링·평가에 `cap + 2·steal`을 쓴다 (Δ는 생성 시점 산출, 캐싱 금지).
